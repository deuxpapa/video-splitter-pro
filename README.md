# Video Splitter Pro

大きい動画も、端末に丸ごと読み込まずに分割できるWebアプリです。
「かんたん動画分割」の後継版で、動画ファイルを少しずつ読み込みながら処理する方式に作り替えています。
Safariで開いて「ホーム画面に追加」すると、アプリのように使えます。

## 作られた経緯

前身の「かんたん動画分割」は、動画ファイルを丸ごと端末のメモリに読み込んでから処理する方式（ffmpeg.wasm使用）でした。実機検証で、337MBの動画は成功したものの、724MBの動画は分割ボタンを押してから約2秒でタブがクラッシュすることが確認され、「動画を丸ごと読み込む」という設計そのものが根本原因と判明しました。本アプリはこの制約を取り除くため、MP4/MOVコンテナを箱（box）単位で解析できる mp4box.js を使い、ファイルを少しずつ読み込みながら分割する方式で作り直しています。

## 特長

- 動画をどこにもアップロードしない（処理はすべて端末内のブラウザで完結）
- 動画ファイルを少しずつ（8MBずつ）読み込みながら処理するため、動画全体のサイズがメモリ使用量に直結しない
- 再エンコードをしない方式（ストリームコピー）なので、画質を落とさずに分割できる
- 巨大なエンジン（旧版はffmpeg.wasm、約9MB）を毎回読み込む必要がないため、処理が非常に高速（数秒程度）
- 各パーツの撮影日時は、分割した日ではなく元動画のファイル更新日時を引き継ぐ。写真アプリ内では、元動画の直後にパーツ1・2・3…の順で並ぶ

## 公開してiPhoneから使う方法（GitHub Pagesの手順）

このアプリはファイルを開くだけ（`file://`）では、写真の選択やホーム画面追加がうまく動かないことがあります。
無料で簡単な方法として、GitHub Pagesでの公開をおすすめします。パソコンの操作だけで完結し、コマンド入力は不要です。

### 手順1：GitHubのアカウントを用意する

すでにお持ちの場合はこの手順は飛ばしてください。お持ちでない場合は、[github.com](https://github.com/) の右上「Sign up」からアカウントを作成してください（無料）。

### 手順2：新しいリポジトリ（保存場所）を作る

1. GitHubにログインした状態で、右上の「＋」ボタン→「New repository」をクリックします。
2. 「Repository name」に、好きな名前を入力します（例：`video-splitter-pro`。半角英数字が無難です）。
3. 「Public」が選ばれていることを確認します（**Private（非公開）にすると、無料プランではPagesが使えません**。動画そのものはこのアプリの外に出ないので、コードだけが公開されても実害はほとんどありません）。
4. 「Add a README file」などのチェックは入れないままで構いません。
5. 「Create repository」をクリックします。

### 手順3：ファイル一式をアップロードする

1. 作成されたリポジトリの画面で、「Add file」→「Upload files」をクリックします。
2. パソコンでこのフォルダ（`0_VideoSplitterPro`）を開き、中に入っている**ファイルとフォルダをすべて選択**します（`index.html`、`style.css`、`app.js`、`manifest.json`、`sw.js`、`manual.html`、`README.md`、`icons` フォルダ）。
   - ※ `0_VideoSplitterPro` フォルダ自体ではなく、**その中身**を選ぶのがポイントです。
3. 選択した状態のまま、ブラウザの「Drag files here」の枠の中にドラッグ＆ドロップします（`icons` フォルダごとドロップすれば、中の画像も一緒にアップロードされます）。
4. 一覧に `index.html` などが表示されたことを確認し、下にスクロールして「Commit changes」（緑色のボタン）をクリックします。

### 手順4：GitHub Pagesを有効にする

1. リポジトリ画面の上部にある「Settings」タブをクリックします。
2. 左側のメニューから「Pages」をクリックします。
3. 「Build and deployment」の「Source」が「Deploy from a branch」になっていることを確認します。
4. 「Branch」のところで、`main`（または `master`）と `/ (root)` を選び、「Save」をクリックします。
5. 数分待つと、ページ上部に「Your site is live at `https://(ユーザー名).github.io/(リポジトリ名)/`」のように、公開されたURLが表示されます。

### 手順5：iPhoneで開いて、ホーム画面に追加する

1. iPhoneのSafariで、手順4で表示されたURL（`https://(ユーザー名).github.io/(リポジトリ名)/`）を開きます。
2. 画面下の「共有」ボタン（四角から矢印が上に伸びたアイコン）をタップします。
3. メニューを下にスクロールし、「ホーム画面に追加」をタップします。
4. 右上の「追加」をタップします。
5. ホーム画面に増えたアイコンをタップすれば、次回からアプリのように開けます。

### アップデートしたいとき

あとでファイルの内容を直したくなったら、同じリポジトリの画面でファイルを開き、鉛筆マーク（Edit）で編集して「Commit changes」するか、手順3と同じ要領で「Upload files」から上書きアップロードすれば、数分後に公開ページにも反映されます。

### 手元のパソコンで動作確認だけしたい場合

Node.jsが入っていれば、このフォルダで以下のコマンドを実行すると、パソコンのブラウザで確認できます（iPhoneの「ホーム画面に追加」を試すにはインターネット上への公開が必要です）。

```bash
npx serve .
```

## 技術メモ

- 動画の解析・分割には [mp4box.js](https://github.com/gpac/mp4box.js/)（GPAC製、CDN経由で読み込み）を使用しています。ffmpeg.wasmとは異なり、MP4/MOVコンテナを箱（box）単位で読み進める設計のため、動画ファイル全体を一度にメモリへ読み込む必要がありません
- ファイルは `File.slice()` で8MBずつ読み込み、`mp4box.js` の断片化（フラグメンテーション）APIでストリームコピー（再エンコードなし）のまま、映像・音声トラックを区切ります
- `mp4box.js` はトラックごとに別々の初期化セグメント（moov）を返すため、映像用と音声用のmoovを1つに結合する処理を自前で実装しています（`app.js` の `buildCombinedInitSegment`）
- 各パーツの撮影日時・長さは、全パーツで初期化セグメントを使い回している関係で、そのままだと元動画全体の値になってしまうため、`mvhd`/`tkhd`/`mdhd` ボックスを直接書き換えて補正しています（`app.js` の `patchMp4Metadata`。version 0の32bitフィールドのみ対応）
- 保存はWeb Share API（共有シート）経由です。「ビデオを保存」「"ファイル"に保存」などを明示的に選んでもらう方式のため、保存先が分からなくなりにくく、保存の成否も画面に反映されます。この機能が使えないブラウザ（PCのブラウザなど）では、従来のダウンロード方式に自動で切り替わります
- 対応ブラウザは最新のSafari（iPhone）を想定しています。PC版Chromeでも動作します
- 実機検証の結果、337MBの動画は成功（処理1秒）したものの、724MBの動画は進捗の途中でクラッシュすることが確認されました。原因は入力側ではなく**出力側**にありました。`splitVideo()` が、切り出した各パーツ（生のArrayBuffer、1パーツ最大113MB程度）を、動画全体の読み込みが完了するまで配列に溜め込んでから、まとめてBlob化していたため、大きい動画では結局「元動画とほぼ同じ量のデータ」が同時にメモリ上に存在してしまっていました。これを修正し、各パーツができた時点で即座に日時を書き換えてBlob化し、生のArrayBufferへの参照をすぐに手放すよう変更しました（`app.js` の `emitIfReady`）。Blobは生のArrayBufferよりメモリ圧迫が少ない傾向があるため、この変更でも改善しない場合は、mp4box.js自体の既知のメモリ保持問題（GitHub issue #430など）が別途影響している可能性があります
